# Неделя 8 — BUILD SPRINT: TrustPay MVP

Дата работы: 5 ноября 2026, Asia/Almaty. Только локальная тестовая сеть; Devnet/mainnet не разворачивались.

## Что реализовано

Anchor escrow и React-приложение с подключением Phantom. Создание и финансирование атомарны. Заказ хранит client, freelancer, mint, amount (u64 в минимальных единицах), id, title, status, bump. ID уникален в пределах заказчика; PDA не позволяет повторно создать тот же заказ.

| Инструкция     | Подписант  | Переход                   | Перевод                          |
| -------------- | ---------- | ------------------------- | -------------------------------- |
| `create_order` | client     | → Funded                  | client token account → vault     |
| `submit_work`  | freelancer | Funded → Submitted        | —                                |
| `allow_cancel` | freelancer | Funded → CancelApproved   | —                                |
| `release`      | client     | Submitted → Paid          | vault → freelancer token account |
| `refund`       | client     | CancelApproved → Refunded | vault → client token account     |

Vault — token account с authority равным PDA заказа. Клиент не имеет его приватного ключа. Программа подписывает CPI через seeds заказа. В инструкциях проверяются canonical PDA, подписант, отношения has_one, владельцы и mint token accounts, точный Token Program ID. Суммы переводятся через `transfer_checked`. Rent оплачивает заказчик; token accounts получателей интерфейс создаёт идемпотентно в той же транзакции, что и выплату/возврат.

После терминального статуса инструкции выплаты/возврата отклоняются. Аккаунт заказа не закрывается: это сохраняет on-chain историю и исключает повторное использование PDA. Непредусмотренных методов изменения суммы, участников или mint нет.

Frontend показывает только заказы подключённого кошелька, с отдельными ролями, фильтрами, деталями, статусами и последними 20 реальными транзакциями заказа. Суммы переводятся в минимальные единицы через BigInt/BN без потери точности Number. После отправки приложение проверяет статус именно отправленной подписи, затем перечитывает RPC. Таймаут не выдаётся за подтверждение. Есть responsive layout и светлая/тёмная тема.

## Ограничения

- Нет арбитража, истечения срока, автоматического возврата и загрузки файлов. `submit_work` — on-chain отметка, сам результат передаётся вне приложения.
- Отмена возможна только после согласия исполнителя **до** сдачи. После сдачи несогласие сторон может заблокировать тестовые средства навсегда. Ограничение показано до создания заказа.
- Согласие на отмену необратимо: после него возможен только refund. Одностороннего вывода средств заказчиком нет.
- Только классический SPL Token Program; Token-2022 не поддерживается. Любой mint проверяется в выбранной тестовой сети, сумма обозначается вместе с адресом mint, без фиктивного тикера/USD-оценки.
- Нет sweep для случайно присланных в vault излишков и возврата rent. Переводится ровно согласованная сумма.
- Список заказов читает все аккаунты Order и фильтрует их по кошельку; индексация для больших объёмов — дальнейшее расширение.
- Счётчики до подключения кошелька/получения данных не подтверждают наличие данных. Реальных примеров платежей в UI нет.
- Программа не проходила независимый аудит. Обнаруженные npm advisory описаны ниже; не использовать с реальными средствами.

Браузерная проверка обнаружила реальный `Buffer is not defined`, хотя TypeScript и production build проходили. Добавлен браузерный alias Buffer и отдельный полифилл, загружаемый до Solana SDK; повторная проверка прошла.

Повторно проверен стандартный `anchor test --skip-build`: Anchor сам запустил свежий validator и загрузил программу; результат — **11 passing (12s)**. Program ID в Rust, Localnet/Devnet конфигурации и IDL совпадает.

Интеграционные тесты проверяют: депозит и состояние; выплату и запрет повторной выплаты; согласованную отмену, возврат и запрет повторного возврата; чужие подписи; неправильные статусы; подмену vault, mint или получателя; нулевую сумму; пустой/слишком длинный UTF-8 title; дублирующий ID; недостаточный баланс и атомарный rollback; self-dealing; чужой источник токенов.

### Проверка браузера с реальными локальными транзакциями

Дополнительно успешно выполнен `npm run test:browser`: два одноразовых кошелька, создание/депозит → сдача → выплата, создание ATA получателя, точный баланс, отдельная согласованная отмена → возврат, история реальных транзакций. Проверка использует тестовый wallet provider и настоящие подписи на Localnet; расширение Phantom не подменяется в продукте. Приватные ключи живут только в памяти процесса. Скриншоты QA сохраняются в игнорируемой `.anchor/browser/`.

SBF-сборщик выдал предупреждение о syscall-символах, поскольку `sdk/sbf/syscalls.txt` в установленном официальном CLI 2.1.0 имеет нулевой размер. Программа успешно развёрнута и все операции выполнены на validator 2.1.0. Дополнительно есть предупреждение о `realloc` в макросах Anchor и о неизвестном старому SBF Cargo ключе resolver; проверки не скрывают эти сообщения.

Anchor 0.31.1 автоматически использовал nightly для генерации IDL; host `cargo check` выполнялся на stable, а SBF — на собственном Rust 1.79 из platform-tools v1.43.

### npm audit

На момент проверки: **27 advisory (1 low, 20 moderate, 6 high, 0 critical)**. Проверка выполнена; для закреплённого legacy Anchor/Solana стека есть advisory в прямых и транзитивных зависимостях. Среди корневых причин: bigint-buffer, toml, uuid, stream-json, serialize-javascript. Полный текущий отчёт воспроизводится через `npm audit`; количество предупреждений может меняться вместе с advisory registry. Совместимого автоматического исправления для всех пакетов нет. `npm audit fix --force` не применялся, поскольку предлагает несовместимые откаты SPL SDK. Эти результаты не скрыты и не означают, что приложение прошло security audit. Миграция стека требует отдельной проверки совместимости.
